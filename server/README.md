# Production cache setup

The live audit on 20 November 2026 saw roughly 1.05 seconds of document response time and `CF-Cache-Status: DYNAMIC`. Local Lighthouse scores do not include that origin/network delay.

The server sends `Cache-Control: no-cache` for HTML so browsers revalidate, plus `Cloudflare-CDN-Cache-Control: public, max-age=60` for Cloudflare. Hashed assets retain their one-year immutable cache. No personalized HTML is generated by this static server.

After deploying the server changes, add **one** Cloudflare Cache Rule for the homepage. [cloudflare-cache-rule.json](./cloudflare-cache-rule.json) contains the rule object for the `http_request_cache_settings` phase. Add it to the existing rules; do not replace the zone's ruleset.

In the Cloudflare dashboard, choose **Caching → Cache Rules → Create rule**:

- Custom expression: `(http.host eq "brighty.pro" and http.request.uri.path in {"/" "/index.html"})`
- Cache eligibility: **Eligible for cache**.
- Edge TTL: **Use cache-control header if present, bypass cache if not**.
- Browser TTL: **Respect origin**.
- Keep the standard cache key and existing asset rules.

Cloudflare does not cache HTML by default. The origin header and the rule are both required; this file does not configure the live Cloudflare account. See [Cloudflare's cache rule settings](https://developers.cloudflare.com/cache/how-to/cache-rules/settings/) and [CDN header precedence](https://developers.cloudflare.com/cache/concepts/cdn-cache-control/).

On each release, retain the previous build as `dist-prev`, reload PM2 with the updated `ecosystem.config.cjs` environment, then purge `https://brighty.pro/` and `https://brighty.pro/index.html` in Cloudflare. The server can serve missing hashed assets from `PREVIOUS_DIST_DIR/assets` while cached pages and open tabs finish. Keep that directory for at least the cache lifetime; preserve older hashed assets separately if deploying several times within a minute.

Verify a warm request returns `CF-Cache-Status: HIT` (the first can be `MISS`), while the browser-facing header remains `Cache-Control: no-cache`. Check the page title and entry script match the new release, then run fresh mobile and desktop PageSpeed tests. Cache rules that override this one, Cloudflare Development Mode, or upstream headers can prevent a hit.
