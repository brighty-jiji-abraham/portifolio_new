# Brighty's portfolio

A React and Three.js portfolio centred on Brighty Jiji Abraham. The website opens directly inside a shared 3D universe, with Brighty's profile beside Earth and its orbiting technology rings.

## Run locally

```sh
npm ci
npm run dev
```

Open the local URL printed by Vite, including the configured `/portifolio_new/` base path. `npm run build` produces the static site in `dist`; `npm run preview` serves that build locally.

Run `npm run lint` for static checks and `node --test tests/*.test.mjs` for animation-sound timing and search metadata regressions.

## Explore

- The universe is the main portfolio. There is no entry button or scroll-based camera track. The opening composition places the profile alongside Earth on desktop and below it on phones.
- Home, Skills, Work, Journey, and Contact start guided flights through the same world. The destination's information opens on arrival. Browser Back/Forward and direct links such as `#skills` or `#contact` work; reloading a destination opens it immediately.
- Information panels are anchored in 3D space and move in perspective during flight. Their shared camera composition adapts to desktop, portrait phones, and landscape screens. There are no page crossings, cutscene captions, or section backgrounds layered over the universe.
- Skills are a 3D network of luminous stars, technology icons, and fine curved connections. Select a category or a star to explore all 57 tools; matching-project links fly to the selected project. Work contains all 22 projects through floating screens, a menu, and previous/next controls. Public projects include links to their GitHub source in both views. Kingdom Chess has a dedicated chessboard exhibit, preview tile, and illustration in the text view.
- Journey is a personal constellation with stellar light, a faint dust cloud, and light moving along its chronological path. Its origin is labelled **My beginning** without displaying the exact birthday. Career stars show the roles and teams; education, certifications, and community activities remain available inside the panel.
- Contact uses the same Earth as the opening scene. **Preview a signal around Earth** is a local animation. The form uses FormSubmit with validation, sending, success, and retry states. Drafts survive dismissing the panel and navigating to another destination within an exploration session.
- **Fly freely** dismisses the panel. Drag space to look around, use W/A/S/D to fly, Q/E to descend/ascend, Shift to boost, and arrow keys to look. Phones have hold-to-fly thrusters. Movement interrupts autopilot; **Stop flight** brakes immediately. Escape closes information or stops flight, keeping the visitor inside the portfolio. Typing and scrolling inside a panel do not control flight.
- The theme button switches light/dark mode for both the interface and 3D materials, with local persistence. The **Sound** button enables a quiet universe ambience beneath the existing background music. Its adjacent arrow opens independent **Universe ambience** and **Black hole effects** volume sliders. Levels are shared between both views and remembered locally; sound still starts off after a reload. The universe level also controls background music, interface ticks, and the project animation sounds. Project cues play only while viewing Work and stop with pause, reduced motion, hidden tabs, or navigation away. **Portfolio options** contains pause/resume motion and **Text view**. Reduced motion bypasses automatic flights and decorative animation while allowing explicit, slower astronaut movement.
- **Black hole** in the header starts a 22-second approach using the current universe scene and camera. Earth, the stars, and the black hole retain their exact starting positions as the view turns and moves toward the horizon. The fullscreen controls have pause/resume, a seekable timeline, replay, and **Return**; Escape also restores the original camera, portfolio section, and keyboard focus. Reduced motion starts at that same departure view with a manually controlled timeline. The flight uses one renderer and pauses in background tabs.
- With sound enabled, the flight fades out the background music and builds a deep rumble, bass harmonics, and stereo rushing air as the horizon approaches. Seeking updates the mix, pause fades to silence, and replay starts the build again. Return brings back the universe ambience and music. Muting or switching tabs fades and suspends audio; sound can also be enabled directly inside the flight.
- Text view is a complete, accessible scrolling portfolio with a **3D view** return button. Browsers without WebGL use this view automatically. It has no large transition gaps or scene placeholders.
- Rendering pauses when the page is hidden. Automatic graphics quality adapts resolution to the device's sustained frame rate and texture downloads to the connection; capable phones can use their full native resolution. Models and textures are loaded separately from the initial interface.

## Scene structure

`PortfolioJourney.jsx` owns selections and switches between the primary universe and `TextPortfolio.jsx`. `useAstronaut.js` manages navigation, browser history, and keyboard flight. `AstronautView.jsx` supplies the main navigation, settings, and touch controls. `usePortfolioSettings.js` shares theme and sound settings between both views.

`Universe.jsx` defines the shared world. `WorkerScene.jsx` runs it in an OffscreenCanvas worker on supported browsers, with `Scene3D.jsx` providing the same renderer on the main thread as a fallback. `AstronautCamera.jsx` handles free flight, guided camera paths, and planet collision boundaries. `FittedWorld.jsx` positions every exhibit at its universe coordinates, independent of the document layout. `InformationPanel.jsx` renders the profile immediately in the main interface, using the same responsive composition from `spatialLayout.js`. Once the renderer starts, `WorldInformation.jsx` updates that existing panel's perspective from the live camera. The content stays mounted across the handoff, preserving animations, native links, inputs, focus, and scrolling. `UniverseDetails.jsx` and the contact form load on first use and stay mounted afterward, preserving drafts.

`EarthWorld.jsx` supplies both Earth scenes, `NeuralSkills.jsx` renders the skill network, `CareerConstellation.jsx` renders the origin and career stars, and `WorldModels.jsx` renders project exhibits and the contact signal. Content lives in `src/data/profile.js`, `skills.jsx`, `projects.js`, `experience.js`, and `constellation.js`. The shared profile supplies both views with the same headline, biography, contact details, and introductory statistics. The constellation is a personal illustration.

## Assets

The universe uses a locally hosted [NASA Deep Star Map](https://svs.gsfc.nasa.gov/3895/) and lunar color/elevation maps from [NASA's CGI Moon Kit](https://svs.gsfc.nasa.gov/4720/). Full credits and original download links are in `public/textures/CREDITS.txt`. These three textures add approximately 2.75 MiB to the scene assets. The distant sky follows camera translation without rotating with the observer, keeping it continuous during free flight.

`PlanetEarth.jsx` combines the existing Earth color, city-light, water, and cloud textures with directional sunlight, a day/night boundary, ocean reflections, and a thin atmospheric rim. Clouds and Earth rotate slowly; the textured Moon follows a tilted orbit. The technology satellites remain as quieter portfolio details. Light mode has a layered blue sky with bright stars, white information panels, and darker technology icons and navigation controls.

`BlackHole.jsx` adds a distant, camera-relative landmark with a dark shadow, a lensed accretion disk, asymmetric brightness, and visibly flowing gas. Hot arcs orbit at different speeds across the disk, fine filaments drift inward, and its halo varies gently. Its bounded shader uses an artistic ray-bending approximation inspired by [NASA's black-hole visualization](https://www.nasa.gov/universe/nasa-visualization-shows-a-black-holes-warped-world/); it is not a scientific simulation. It uses no additional image, video, or model downloads and cannot intercept exhibit clicks. On phones its smaller placement keeps the skill and career stars clear.

`BlackHoleJourney.jsx` loads its controls only when requested, in a transparent modal above the live universe. `BlackHoleCinema.jsx` captures the existing camera and black-hole transform, takes over that camera during the approach, and restores its pose on exit. It keeps the same black-hole mesh and shader throughout; `blackHoleFlight.js` supplies the flight timing. Lensing gradually samples the existing NASA map in the universe's sky orientation, and light mode gently darkens during departure. The visual direction references [DNEG's work on Interstellar](https://www.dneg.com/news/new-black-hole-imagery); the flight is an artistic sequence rather than a physical model of crossing an event horizon. No film footage, music, or new texture downloads are needed.

`src/audio/cosmicAudio.js` synthesizes the original ambient and cinematic effects with Web Audio: filtered stereo noise, slowly moving air, and low oscillators with audible upper harmonics. Journey position controls their pitch, filters, and level, including a fade at the final horizon. Smoothed parameters and a master compressor keep transitions controlled. `useSoundscape.js` creates one shared audio graph only after a sound-button gesture, mixes the existing `bg-music.m4a` through it, suspends it when silent, and releases it on unmount. These effects add no audio assets or dependencies.

`projectEffects.js` adds short, quiet taps, paper rustles, scanning tones, and completion chimes to that same graph. `projectCues.js` places cues on each exhibit's animation clock; chess derives landing and capture cues directly from its moves. Frozen frames cannot repeat sounds, and resuming or unmuting never replays missed events. Switching exhibits cancels remaining notes, including delayed layers. The effects reuse the existing noise buffer, limit simultaneous voices, release transient nodes when finished, and follow the Universe ambience slider independently of the black-hole mix.

`StellarAtmosphere.jsx` supplies local shaders for stellar cores, optical halos, softly drifting dust, and faint nebula wisps. Skills use these in place of solid badges and rims; Journey uses them in place of faceted markers. Connections carry small moving lights, selection can send a signal through the skill network, and tracing the career path follows a moving comet. A slight idle turn gives each constellation depth while labels remain readable. Distant exhibits are hidden while reading Skills or Journey to prevent their labels overlapping; they reappear for free flight. All decorative motion—including the black hole, stars, clouds, connections, Earth, and Moon—uses the same clock and freezes under **Pause motion** or reduced-motion preferences.

Project previews show short project titles and field-specific diagrams instead of rotating generic shapes. `ProjectPreview.jsx` creates these lightweight textures locally. The selected project is outlined; the existing menu and previous/next controls remain the accessible alternatives. All 22 projects have distinct animated exhibits: chat messages travel through channels, RAG retrieves documents, publishing writes a page, vision scans images, a ballot enters a box, a cart fills, a collaborative editor syncs, Bingo completes a line, and a treasure chest opens after following clues. Client sites demonstrate responsive layouts, and the portfolio exhibit contains a miniature orbiting universe. These are conceptual illustrations, not recordings of the products.

`projectVisuals.js` maps each project to its animation. `scene/exhibits/` groups the system, media, and interactive sequences around reusable materials and geometry. Only the selected exhibit mounts, and its sequence restarts when selected. `useExhibitClock` derives playback from the shared universe clock, so pause and reduced-motion preferences also stop every project animation. The sequences use local geometry and reuse the existing Earth textures; no animation library, video, or new downloaded model is required. `SceneReflections.jsx` loads the same softbox reflections baked ahead of time, avoiding PMREM generation on each visit.

The neural network, project screens, constellation, and orbit paths are built locally. The career constellation has no outer decorative ring or tick marks; its interactive stars and connecting paths remain. Project screens use portfolio titles and technologies with abstract diagrams. No runtime asset CDN is required. Legacy Kenney and NASA models retain their bundled credits.

## Production bundles

`vite.config.js` uses Rolldown chunk groups to separate Three.js's core and WebGL renderer from the portfolio code. Scene and text views retain their dynamic imports, and the black-hole controls load on demand. The standard 500 kB chunk warning stays enabled; the largest minified JavaScript chunk is approximately 395 kB with the current dependencies. The worker bootstrap and DOM bridge are small; the engine and scene are loaded inside the worker. The fallback engine downloads only when needed. Separating the engine also lets browsers cache it independently of portfolio edits.

The profile paints before graphics initialization. On supported browsers, a module worker owns the existing Three.js scene, WebGL context, shader compilation, texture uploads and animation loop. The page retains accessible HTML, sound and volume controls, and forwards input and preferences; the worker sends camera projections and selection events back. Canvas labels use OffscreenCanvas, photographic maps decode to ImageBitmap in the worker, and SVG icons retain their exact colors through asynchronous browser decoding and bitmap transfer. No animations or quality tiers are removed. Worker initialization failures fall back to the original main-thread renderer, and unavailable WebGL still opens Text view. `StartupRenderer.jsx` submits shader compilation, yields to the browser, and prepares first-use program metadata within a per-frame budget before drawing. It uses non-blocking compile status where supported and spreads work across frames on other drivers. `SceneTextureLoader.js` uses worker bitmap requests, or normal image requests with asynchronous bitmap decoding in the fallback, without resizing or changing pixels, orientation, or alpha; unsupported decoding falls back to the original image. This reduces texture-upload work while keeping the same maps and shaders. Bandwidth observations only update React when the network quality tier changes, avoiding unnecessary scene reconciliation.

Universe textures are imported from `src/assets/universe/` so Vite fingerprints their URLs and the production server can cache them immutably. The balanced set retains the original dimensions, with lossless night lights and cloud alpha and high-quality WebP for the sky and Earth color. The original set preserves the source color maps, including the 4K star map. A lightweight set supplies smaller maps for constrained connections and devices. Only the selected set downloads. The source maps and NASA credits remain in `public/`. Run `python build/optimize-images.py` with Pillow installed to regenerate these copies and the small profile portrait; the text view retains its full-size portrait.

`room-environment.png` is a data texture: two opaque RGB pixels preserve the six original bytes of each RGB half-float PMREM texel. `ReflectionTextureLoader.js` restores those HDR values without tone mapping or quantization. To regenerate it after a Three.js/lighting change, serve the repository with `python -m http.server 4196 --bind 127.0.0.1`, open `/build/bake-reflections.html`, and save its download into `src/assets/universe/`. Open the same tool with `?size=128` for `room-environment-light.png`. Then run the image optimization script for lossless PNG compression. Use the same Three.js version and `RoomEnvironment` settings as the scene. This tool is not a production entry point.

Icon textures serialize the static `react-icons` SVG trees directly, so the browser no longer downloads React's server renderer. `node --test tests/*.test.mjs` checks every used icon against the React renderer, quality policy behavior, discovery, and sound cues.

## Adaptive graphics quality

The existing options menu contains Automatic (default), Maximum quality, Balanced and Lightweight settings. The choice is saved locally. Layout, camera paths, animation timing, interactions and audio are shared by every setting.

Automatic chooses texture downloads using connection estimates and Data Saver, with a device-memory guard. Existing uncached resource timings from both the page and worker correct optimistic connection estimates and provide a fallback where the [Network Information API](https://developer.mozilla.org/en-US/docs/Web/API/Network_Information_API) is unavailable; no speed-test file is downloaded. Fast connections can use the original 4K sky and 2K Earth maps. Slower connections start with the lightweight set. Auto can upgrade when the connection improves, and keeps already downloaded detailed maps when the connection slows. A black-hole flight retains its current sky until return, so an upgrade cannot reset its shader or camera continuity.

Rendering quality is evaluated separately using actual frame times, following the [React Three Fiber performance-scaling approach](https://r3f.docs.pmnd.rs/advanced/scaling-performance). Sustained smooth frames increase resolution, planet detail and texture filtering; sustained slow frames reduce rendering load. Separate thresholds and a cooldown prevent rapid switching, and hidden/paused/reduced-motion scenes do not contribute samples. The highest level supports native 3× mobile rendering, desktop supersampling, finer planet meshes and up to 16× anisotropic filtering, with a roughly 8.3-million-pixel ceiling. Maximum quality explicitly requests that level and the original maps. These are device capabilities and real frame measurements, with the same behavior for visitors and audits.
